# 基于现有程序的拉曼测温实施方案

## 目标

在不推翻现有 LabVIEW 旧工程的前提下，实现下面这条链路：

1. 显微镜下激光照射样本
2. 旧 LabVIEW 程序完成 CCD 采谱和位移台运动
3. 将采到的光谱转换成拉曼峰位
4. 根据标定公式换算样本温度
5. 将温度结果导出到指定文件夹

## 当前工程已经具备的能力

通过对旧 VI 的依赖分析，当前工程已经具备：

- HORIBA / JY CCD 采集
- HORIBA / JY 单色仪控制
- XPS-Q8 XY 位移台控制
- 光谱数据保存

对应旧 VI：

- `JY .vi`
- `Spectral mode.vi`
- `Image mode.vi`
- `JY Mono.vi`
- `jymove.vi`

## 最合理路线

当前最合理路线不是直接重写旧 VI，而是：

- 保留旧 LabVIEW 采集与位移逻辑
- 在采集结束后调用新增的温度后处理脚本
- 先实现离线/半在线温度计算
- 等流程验证稳定后，再把相同算法搬回 LabVIEW 子 VI

这样做的原因：

- 旧系统已经跑通过硬件链路
- LabVIEW 二进制 VI 不适合在当前环境直接自动生成
- 温度反演核心是算法层，先独立验证更稳

## 现在就能跑通的流程

### 1. 准备标定参数

编辑：

`Calibration/raman_temperature_calibration.json`

关键参数：

- `reference_shift_cm-1`: 参考温度下的拉曼峰位
- `slope_a`: 温度-峰移线性拟合斜率
- `intercept_b`: 截距
- `start_cm-1`, `end_cm-1`: 搜索目标峰的波数窗口

当前文件里的值只是模板，不应当直接当最终实验值。

### 2. 准备波数轴

这是当前旧数据里最关键的缺口。

现有 `Save/08.20/*.xls` 基本是单列强度数组，长度 1024 点，没有直接保存波数轴。

所以正式测温前必须二选一：

1. 从 LabVIEW 里把每次光谱的波数轴一起保存出来，建议保存成两列：
   - 第 1 列：wave number
   - 第 2 列：intensity
2. 或者在仪器参数固定时，只导出一次固定波数轴，保存为单独文本文件：
   - `Calibration/wavenumber_axis.txt`

脚本支持这两种方式：

- 单独 `axis file`
- 或在配置里填 `axis_start_cm-1` 和 `axis_step_cm-1`

### 3. 用旧程序采谱

建议先从单点测温开始：

1. 用 `Image mode.vi` 找点、对焦
2. 用 `Spectral mode.vi` 采目标点光谱
3. 保存光谱到指定文件夹

再做多点或 Mapping：

1. 用 `jymove.vi` 控制 XY 位移台
2. 每到一个点采一条光谱
3. 用文件名或位置表记录点位

### 4. 运行温度后处理

PowerShell：

```powershell
.\tools\run_temperature_pipeline.ps1 `
  -InputPath ".\Examples" `
  -OutputCsv ".\Results\Temperature_Data\synthetic_result.csv" `
  -Calibration ".\Calibration\raman_temperature_calibration.json" `
  -AxisFile ".\Examples\synthetic_axis.txt" `
  -Pattern "synthetic_spectrum.txt"
```

Python 直接运行：

```powershell
python .\tools\raman_temperature_offline.py `
  --input ".\Save\08.20" `
  --output ".\Results\Temperature_Data\temperature_results.csv" `
  --calibration ".\Calibration\raman_temperature_calibration.json" `
  --axis-file ".\Calibration\wavenumber_axis.txt" `
  --pattern "*.xls"
```

### 5. 输出结果

脚本输出 CSV 字段：

- `filename`
- `x_um`
- `y_um`
- `peak_shift_cm-1`
- `peak_intensity`
- `baseline`
- `noise`
- `snr`
- `temperature_c`
- `quality`

## 与 LabVIEW 的连接方式

当前推荐用 LabVIEW 的 `System Exec.vi` 在采谱结束后调用：

```powershell
powershell.exe -ExecutionPolicy Bypass -File tools\run_temperature_pipeline.ps1 ...
```

建议连接点：

1. 单点模式：
   `Spectral mode.vi` 保存光谱后调用脚本

2. Mapping 模式：
   `jymove.vi` 扫描全部结束后统一调用脚本处理整个文件夹

## 为什么先不直接把温度算法塞进旧 VI

因为当前工程里最不确定的是：

- 光谱保存格式
- 波数轴来源
- 样品标定参数是否可信

这些在离线脚本阶段更容易查清楚。  
等这条链稳定后，再把同样的 3 个模块搬进 LabVIEW：

- `Find_Raman_Peak.vi`
- `Calculate_Temperature.vi`
- `Export_to_CSV.vi`

## 下一步建议

推荐按这个顺序推进：

1. 在 `Spectral mode.vi` 确认能导出波数轴
2. 用已知温度样品做标定，更新 JSON 参数
3. 先跑通单点测温
4. 再接入 `jymove.vi` 做温度 Mapping
